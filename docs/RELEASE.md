# Release and discovery

## Publication gate

- Run the documented demo, complete test suite, and local release checker in a fresh extracted archive.
- Run a dedicated secret scanner and manually inspect the exact release contents. The bundled pattern checker is limited. Never publish its private-term configuration.
- Test profile/skill setup in a real Grok Bot account and record version/date, import method, permissions and outcomes. Until then, keep the README's compatibility caveat.
- Verify you own the code being licensed; preserve external notices and data-source terms. No external market dataset or third-party logo ships here.
- Publish this folder as a new repository with a fresh history. Do not publish a parent private workspace, its memory, or its .git history.
- Enable private vulnerability reporting. Use a genuine reporting channel, not a made-up address.
- Let hosted CI run successfully before adding a repository-specific passing badge or tagging a release.

The code licence is MIT, but source data and the Grok Bot platform have separate terms and access costs. No trademark clearance or name reservation is claimed.

## Positioning

**IRIN: source-linked AI-infrastructure research checks for Grok Bot.**

Lead with the actual pain point: a convincing AI thesis is hard to audit. Show the synthetic pass/missing/stale examples and an expandable failed-rule report. A small, reliable tool is easier to trust than a broad claim of financial autonomy.
